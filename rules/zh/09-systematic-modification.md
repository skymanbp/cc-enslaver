# 规则 09 — 系统式修改，禁止打补丁（systematic-modification · no-patch-style）

## 原则

> **修改必须是系统性的、完整性的更新，不是局部打补丁。**

打补丁式修改的典型特征：

- 看到症状改症状（"加一行 if 把异常吞掉"），不改根因；
- 局部塞 `try / except: pass` / `# noqa` / `@ts-ignore` / `// eslint-disable` 静音报错；
- 同一文件同一会话里反复小幅 `Edit`（rolling patches），每次只动 1-3 行；
- 在调用点局部包一层 wrapper / try 来"修好"，而真正的 bug 在被调函数；
- 把超时拉长 / 把断言放宽 / 把测试改宽容；
- 注释掉失败的测试而不是修代码；
- 在新代码里塞 TODO / "暂时这样" / "之后再做"；
- 对同一根因的 N 处症状逐个点对点修补，而不是在确诊的起源处做一次统一修复（v0.28——在文本 / 注入层强制；它的同文件形态由 v0.13 频率层拦截）。

这些都不是"修复"，是**延后**问题。rule 09 把它们提到一类硬性禁令，并在 hook 层落实**物理拦截**。

## 必须做（MUST）

### 修改之前

1. **找到真正的根因**（rule 03）—— 不是"在哪里报错"，而是"为什么会这样"。
2. **确认根因证据**（rule 01 验证）—— 通过 Read / Grep / 命令输出**当场验证**根因假设。
3. **梳理影响范围**（rule 02 七问的"连带影响"）—— 列出根因牵涉的所有上下游。
4. **比较至少 2 个修复方案**（rule 08 第 6 项）—— 在简洁性 / 性能 / 与现有架构契合度 / 后续维护 4 个维度对比。

### 一个根因，一次统一修复（v0.28）

点对点打补丁——把每个观察到的失败当成一次独立的小修——被禁止。
问题出现时，唯一被接受的形态是**溯源 → 确诊 → 统一修复**：

5. **溯源到最上游根因**（rule 03 上游阶梯）：沿因果链上爬，直到答案
   是机制 / 设计决策 / 缺失不变量为止，并显式说明为什么停在你停下
   的地方。
6. **确诊先于动手**：根因假设必须在写下修复的第一行代码*之前*，被
   第一方探针 / 复现 / 红测试证实（rule 01）。
7. **枚举"类"，不是枚举实例。** 确诊的根因定义了一个缺陷的*类*；你
   观察到的那个实例只是碰巧先浮出水面的那个。全库清扫该类的每一个
   同类实例（Grep 定位、Read 确认——rule 04；清扫要汇报——rule 12）。
   范围注：清扫是"把被报告的问题修好"的一部分，不是范围溢出——
   rule 07 禁的是*没被要求*的改动。但当枚举出的类实质性扩大了用户
   请求的可见范围时，先把枚举结果上呈、拿到用户的决定，再做一趟式
   修复。
8. **机制只修一次。** 一次系统性修改，拆掉产生问题的机制，并在同一
   趟里覆盖枚举出的每一个实例。N 个症状共一个根因 = **一次**修复
   ——绝不是 N 个补丁，也绝不是"修被报告的那几个，剩下的同类不管"。
   "一次"的单位是机制，不是 diff 的体积：最小有效更改仍然适用。
9. **证明这个类已闭合**（rule 06）：验证不仅要重触发观察到的那个
   实例，还要至少重触发类里*另一个*被枚举出的实例。当清扫表明这个
   类只有一个成员时，显式说出来——清扫报告本身就是闭合证据。

实例修补陷阱，在本仓库身上的实测：v0.25.1 点名了一条根因，却只修
了它见过的实例；机制活了下来，到 v0.26 就再生出同一类的新一批缺陷
——其中包括一个倒退。v0.26 随后换掉了机制（33 条 finding → 三个
根因 → 四个统一件），这正是本节规定的形态。同一形状的第二次失败，
是"类"在自我宣告——它施加的是"验证起源是否真的共享"的义务，绝不是
可以无视的巧合。

### 修改之中

10. **修根因，不修症状**（rule 03）—— 修改点应位于因果链的源头，而非现象处。
11. **完整覆盖影响范围** —— 同一根因的所有连带点一并修，不允许"先修一个明天再补"。
12. **不引入补丁标记** —— 见下方"物理拦截"。
13. **新建/更新不变量必须记录** —— 若修改建立了新的不变量（"X 永远 ≠ None" / "必须先获取锁"），在代码或文档中显式声明。

### 批量机械替换（改名 / codemod / sed）

正则匹配你的意图，也匹配它的**同形异义**；而批量替换是唯一一种
"一条规则写错就同时污染上百个文件"的改动形态。动手之前：

1. **先勘察，后写规则。** 枚举目标 token 每一处出现的**真实上下文**并
   *把那份清单读一遍*。一次真实的目录改名里靠这一步抓出的同形异义：
   URL 里的 API 版本号（`…/v3/me`）、DB 表版本（`agent_subtypes v3/613`）、
   schema 区间（`Mesh v3/v4`）、**数学变量**（`v3 = v2 * v1 + …`）、
   函数参数、报告编号（`DIV-V3`）。盲目 sed 会把这六类全改坏。
2. **只改白名单形态。** 绝不"凡是匹配的都替换"——只替换勘察已证明
   确实是你所指的那些。
3. **必须产出拒绝报告。** 白名单拒绝掉的每一处都要打印出来给人读。
   静默跳过与"漏掉一处"在外观上完全无法区分。
4. **算术必须自洽。** 总命中数 = 已改写 + 已跳过 + 已拒绝。对不上就是
   规则错了，不是计数错了。
5. **预期会有正则天生看不见的形态。** token 藏在**正则选择分支**里
   （`^(?:v3|docs)/` —— 它后面跟的是 `|`，不是你所依据的分隔符）；
   token 作**独立参数**（`join(root, "v3", "assets")`）；以及**以它命名的
   符号**（`V3_DIR`）。每一类都需要独立的一趟勘察。
6. **绝不改写寻址历史的路径。** `git show <固定 rev>:<path>` 解析的是
   旧树，那里旧布局才是对的。工作树路径会搬家，寻址历史的路径不能跟着搬。

### 修改之后

14. 走 rule 06 收敛验证——**包括验证 2b**，因为批量替换正是"总数不变而
    构成已变"的典型场景；走 rule 07 任务忠实。

## 物理拦截（hooks）

| 拦截层 | 钩子 | 触发条件 | 动作 |
|---|---|---|---|
| **Edit/Write 内容层** | `PreToolUse(Edit\|Write)` | new_string 含未带 "why" 注释的补丁标记 | **DENY** |
| **Edit/Write 频率层**（v0.13） | `PreToolUse(Edit\|Write)` | 同一文件本会话第 4 次"小幅 Edit" (≤ 10 行 且 < 200 字符) 而无系统式重写（≥ 50 行 / ≥ 1500 字符）介入 | **DENY** |
| **Bash 命令层** | `PreToolUse(Bash)` | `--no-verify` / `--no-gpg-sign` / `chmod 777` / `git rebase --skip` / `--break-system-packages` / `rm -rf` 打到根路径 / `git push --force`（非 `--force-with-lease`） | **DENY**（v0.3 bash_guard，v0.14 扩充；v0.26 起按解析后的 argv 判定） |
| **收尾层** | `Stop` layer (f) | 本轮做了 Edit 但最终回复缺"根因 + 影响 + 方案"标记 | **BLOCK** |

### Edit/Write 频率层 — rolling-patch 计数器（v0.13）

每个文件维护一个**小幅 Edit 计数器** `state.edits_per_file[path]`：

| 分类 | 边界 | 计数器动作 |
|---|---|---|
| **small** | max(\|old\|, \|new\|) < 200 字符 **且** max 行数 ≤ 10 | +1（若预计达到 4 → DENY，**不增**） |
| **systematic** | max 字符 ≥ 1500 **或** max 行数 ≥ 50 | 重置为 0 |
| **medium** | 介于两者之间 | 不动 |

预计到达阈值（4）即 DENY，且**不**增加计数器。这使得后续小幅 Edit 仍然被拦，直到一次系统式重写出现把计数器清零——这正是规则 09 想要的：**重新理解整个文件结构，而不是继续打补丁**。

DENY 时给出的恢复路径：
1. 合并多个待办小改成一次系统式 Edit（new_string ≥ 50 行）；
2. 用 `Write` 整体覆写（content ≥ 50 行）；
3. 停下来 surface 给用户，让其评估是否需要架构级重构。

### Edit/Write 内容层 — 补丁标记清单

下列模式只要出现在 `new_string` 中，且**未在同一段附带 "why" 注释**说明合理性，即被拦截：

| 模式 | 拒绝理由 |
|---|---|
| `try:` … `except …:` … `pass`（全部子句 / 嵌套块 / 单行形） | 静默吞错（rule 03） |
| `#\s*noqa\b`（无理由） | 屏蔽 lint（rule 03） |
| `#\s*type:\s*ignore\b`（无理由） | 屏蔽类型检查（rule 03） |
| `//\s*@ts-ignore\b` / `//\s*@ts-expect-error\b`（无理由） | 屏蔽 TS 报错（rule 03） |
| `//\s*eslint-disable(?:-next-line)?\b`（无理由） | 屏蔽 lint（rule 03） |
| `time\.sleep(…)\s*#\s*(wait|race|workaround)`（含嵌套调用） | 用 sleep 掩盖竞态（rule 03） |

**标记的拼写不等于标记本身（v0.25.1）**：五个单行标记不再要求行尾锚点。

- **CRLF 不再能击穿它们**。旧的 `[ \t]*(?:\n|$)` 锚点匹配不到 `\r\n`，于是在
  Windows 上这五个检测器全部静默失效。
- **尾随文本不再让标记隐形**。`// @ts-ignore: TODO` 此前**根本不匹配** —— 它被
  放行，而理由检查从未运行，反倒是裸形态被拦。现在尾随文本会被判定：是解释则
  放行，是光秃秃的延期词（TODO / FIXME / HACK / WIP / later）则不放行。
- **散文档**（`.md` / `.rst` / `.txt` / `.adoc`）仍只匹配裸形态 —— 那里的标记是
  被讨论的对象，不是生效的屏蔽。

**吞错行的扫描方式（v0.25，v0.25.1 扩展）**：`try/except: pass` 检测器比对该行的**代码**，而非原始文本：

- 行尾注释不再能绕过它 —— `pass  # TODO later` 照样拦。此前要求 `pass` 必须
  完全裸露，反而让下面那条 why 注释逃生口**对这个标记根本不可达**：加理由注释
  是靠"改变了字符串"让检测器沉默的，理由本身从没被读过。
- **handler 头与吞错行之间的注释行**也不再掩蔽它。那是同一个缺陷换了个拼写：
  把理由写在 `pass` 上面独立一行 —— 最自然的写法 —— 会把 `pass` 挪出扫描器
  视野，于是逃生口仍不可达，而 v0.25 那条自称钉住它的回归测试是因为错误的
  原因才通过的。
- `except Exception: pass` **单行形**会被检出，**嵌套** `try` 会被跟踪（用栈，
  而非单个待定缩进），且一次编辑里的**每个**命中都会被检查 —— 带理由的吞错
  不再掩护后面无理由的那个。
- 一个 `try` 语句的**每个** `except` 子句都会被检查，不再只看第一个。于是那个
  典型形态 —— 先一个窄 handler、再一个吞掉一切的兜底（`except ValueError: log()`
  之后跟 `except Exception: pass`）—— 不再隐形。

**理由必须写在注释里（v0.25.1）**：逃生口此前搜索的是原始的 ±1 行窗口，于是理由
token 出现在**任何可执行代码**里都算数 —— 裸标记旁边有一句 `reason = compute()`
就够了。现在只认注释文本，这本来就是 deny 消息一直声称的契约。

**「什么算注释」改由词法判定（v0.26.0）**：「找第一个 `#` 或 `//`」和「注释从哪里
开始」不是同一个问题：它会找到 `"http://host/#frag"` 里的 `#`、以及**任何** URL 里的
`//`，于是相邻一行 `API = "https://api.example.com"` 就能让检测器沉默 —— 并且通过
共用的逃生口，把 rule 10 的密钥检测器一起关掉。注释提取现在走真正的词法器
（[`lib/srclex.py`](../../hooks/scripts/lib/srclex.py)），随之而来：

- `/* … */` **块注释被认可**（此前完全看不见，合法的相邻 JavaScript/TypeScript
  理由会被误拒）；
- 写在 **docstring 里的理由算数** —— 它是文档不是数据 —— 而普通字符串字面量里的
  token 不算；
- 窗口按**全文**的词法状态判定，而不是孤立地重新词法分析三行（docstring 内部的
  切片自身没有定界符，单看就像裸代码）。

**逃生口不再只认英文（v0.26.0）**：此前表里只有名词 `原因`，于是最自然的中文
「因为」被 DENY，而英文 `because` 放行。现在 `因为` / `之所以` / `理由` / `故意` /
`刻意` / `有意` / `特意` 都是理由 token。相关地，「读起来像真解释」的启发式此前
要求有 ASCII 空格，而中文句子永远没有 —— 现改为按 CJK 字数衡量，于是同一条理由
用哪种语言写都被接受。

**标记在词边界收尾（v0.26.0）**：v0.25.1 去掉行尾锚点后，标记退化成裸子串，于是
`# noquality`、`@ts-ignore-generated`、`eslint-disablement` 都被当成它们仅仅以之
开头的那个屏蔽标记，被误拦。

**允许的形式**：每个屏蔽标记必须在同一行或紧邻上一行/下一行带**理由注释**（含 "because" / "原因" / "因为" / "why" / "正当" / 显式说明），例如：

```python
# noqa: E501  -- URL string exceeds 100 chars; splitting hurts readability
LONG_URL = "https://..."
```

```typescript
// @ts-ignore: third-party lib has incomplete type, see issue #1234
const result = legacy.foo();
```

无理由的裸标记 = 偷懒，被拦截。

## 禁止做（MUST NOT）

- ❌ **症状式修补**：在调用点包 try/except 让异常消失，但**没改根因**。
- ❌ **静默屏蔽**：`# noqa` / `@ts-ignore` / `// eslint-disable` 无 why 注释。
- ❌ **竞态用 sleep 掩盖**：加 `time.sleep(0.5)` 让测试稳定通过 ≠ 修复竞态。
- ❌ **测试放宽**：原测试要求 X==5，改成 X>0 让它过。
- ❌ **超时拉长**：原 timeout=5s 拉到 60s 掩盖性能问题。
- ❌ **注释掉失败测试**：删除 / 注释 / `@skip` 失败用例当作"修好了"。
- ❌ **滚动补丁**：同一文件本会话 ≥ 4 次小幅 Edit 而**没有**一次系统性重写，属于反应式累加。v0.13 起由 `PreToolUse(Edit|Write)` 频率层物理拦截，不再是软纪律。
- ❌ **修一个留三个 TODO**：不允许"先把这个修好其他下次再说"，必须一次性覆盖完整根因影响范围。
- ❌ **盲目批量替换**：跑改名 / codemod / sed 而事先没勘察 token 的真实上下文、没有白名单、或没有拒绝报告。
- ❌ **搬家时改写寻址历史的路径**：交给固定 git rev 的路径必须保持那个 rev 里真实存在的布局。
- ❌ **不变量是封闭集却写成模式黑名单**：若"只有名单内的名字合法"，就枚举那份名单并拒绝其余一切。只拉黑你碰巧见过的几种散件形态，下一种形态会直接走过去——包括在这道门**首次实跑**时。
- ❌ **点对点打补丁**（v0.28）：多处症状共享同一根因，却一处一处各修各的——包括"修被报告的那几处，没被报告的同类不管"。
- ❌ **实例加固**（v0.28）：修好了机制缺陷被观察到的那个实例，机制本身却原地不动、继续再生同类——加固只针对被看见的那一处，从不清扫整个类。

## 自检触发器

下列任一情况出现，agent 必须主动自检本规则：

- 即将做不超过 5 行的"快速修复"；
- 即将写 `try / except: pass` 或 `try / except: ...` 含糊处理；
- 即将写 `# noqa` / `@ts-ignore` / `eslint-disable` 而**不解释为什么**；
- 即将加 `time.sleep` 让测试稳定；
- 即将把测试断言放宽 / timeout 拉长；
- 注释掉 / `@skip` 任何失败的测试；
- 本会话内已对同一文件做过 ≥ 3 次小幅 Edit，仍在打补丁而不是重写；
- 即将跨多个文件跑改名 / codemod / sed，而没有勘察、白名单与拒绝报告；
- 即将为一个规格上是**封闭集**的不变量写一道枚举**坏形态**的守卫；
- 即将修的这个失败，和已经修过的某个**形状相同**——"类"在自我宣告；去诊断共同起源，别修补新冒头的这处；
- 即将动手写修复，却还没说明因果链停在哪里、为什么停在那里；
- 思维链里没有"根因 + 影响范围 + 方案对比"三件套。

## 终止条件

只有当下面**全部**成立时，才允许声称"修改完成"：
