# 规则 10 —— 禁止非必须硬编码

## 原则

> **一个在设计上本应是变量的值 —— 应从配置、环境变量、密钥管理器或
> 传入参数读取 —— 不得被偷懒地内联成源码字面量。**

本规则拦截的典型偷懒就是"设计上应该是变量却被偷懒塞成硬编码内容"——
那些**毫无疑问本应活在代码之外**的字面量：

- 凭证：口令、API key、access key、auth token、client secret、bearer token；
- 私钥材料（PEM `BEGIN ... PRIVATE KEY` 块）；
- 嵌在连接串 / URL 里的凭证
  （`scheme://user:password@host`）。

硬编码密钥不只是脏，它把密钥泄进版本控制、CI 日志和仓库的每一份克隆，
还让轮换变成一次代码改动。把它外部化才是根因修复（规则 03）。

## 硬强制的边界（以及不强制的部分）

忠于本仓库自身保守探测器哲学（"宁可漏报不误报"），只有**毫无歧义、
本应是配置**的类别在写入时被**硬强制**：

| 类别 | 硬强制？ |
|---|---|
| 密钥命名的变量赋一个引号字面量（≥ 8 字符） | ✅ 是 |
| 私钥 PEM 头 | ✅ 是 |
| AWS access-key 字面量（`AKIA…`） | ✅ 是 |
| 连接 URL 内的凭证 | ✅ 是 |
| 魔法数字 | ❌ 仅软提示（易误报） |
| 裸网络端点 / 端口 | ❌ 仅软提示 |

魔法数字与裸端点是*软*提示 —— 评审时提出即可，但**不**由钩子拦截，
因为为它们做硬探测会在合法代码上不停误触发。

## 物理拦截（钩子）

| 层 | 钩子 | 触发 | 动作 |
|---|---|---|---|
| **Edit/Write 内容** | `PreToolUse(Edit\|Write)` | `new_string` / `content` 含未经辩护的硬编码密钥 | **拒绝** |

散文文档（`.md` / `.markdown` / `.rst` / `.txt` / `.adoc` / `.asciidoc`）
与锁文件（`*.lock`、`package-lock.json`、`yarn.lock`、`poetry.lock`、
`Cargo.lock` …）**豁免** —— 它们合法地携带示例值，且是机器生成的。
探测器只针对新写的*代码*。豁免内有一个例外（v0.24）：
`requirements*.txt` / `constraints*.txt` 是依赖清单而非散文 —— 其中
内嵌凭证的 index URL 是真实的泄漏向量 —— 因此尽管扩展名是 `.txt`，
它们仍被扫描。

### 探测器清单

以下内容，当出现在传入内容里**且没有占位值、也没有相邻的 "why"
辩护**时，被拦截：

| 模式 | 示例（仅示意） |
|---|---|
| 密钥命名的标识符 = 引号字面量 | `api_key = "…10+ 字符…"` |
| 密钥命名的**带引号键** = 引号字面量（v0.25） | `"api_key": "…10+ 字符…"` |
| 私钥 PEM 头 | `-----BEGIN … PRIVATE KEY-----` |
| AWS access-key 字面量 | `AKIA` + 16 位大写字母数字 |
| URL 里的凭证 | `postgres://user:pw@host/db` |

带引号键那一行补的是个要命的缺口：此前分隔符必须紧跟在关键字之后（中间只
允许空格），于是键自己的右引号挡掉了 JSON 与带引号键 YAML/TOML 的每一次
匹配 —— 那恰恰是被提交的凭证最常见的形态，而 `.json` 是完全会被扫描的。
结果是罕见的裸键形态被拦下，最常见的那种反而放行。

一个值被当作无害占位（不标记）的条件是：它含有 `example` / `changeme` /
`your-` / `<…>` / `${…}` / `dummy` / `redacted`，或是一次环境读取
（`os.environ[…]`、`getenv`、`process.env`）。纯字母 CamelCase 形状的值
（`^[A-Z][A-Za-z]*$`）也被跳过（v0.24）：`password: "SecretStr"` 是
Python 前向引用类型注解，不是凭证 —— 真实密钥总带数字或符号。

### 逃生舱 —— 把"非必须"操作化

用户的范围是*非必须*硬编码。"必须 / 示例 / fixture"字面量在其所在行、
或紧邻行（±1）携带辩护 token 时被放行：`because` / `原因` / `essential` /
`必须` / `example` / `fixture` / `placeholder` / `占位` / `sample` /
`test data`。一个没有任何辩护的裸密钥 = 非必须情形 = **拒绝**。

## 必须做（MUST）

1. **外部化密钥** —— 从环境或密钥库读取；真实值只留在未被追踪的
   `.env` / 密钥库里。
2. **标注真正的占位** —— 用明显的占位值，或加一条相邻辩护注释，
   让检查能区分示例与泄漏。
3. **暴露即轮换** —— 若真实密钥曾被提交，视其为已泄露并轮换，
   不要只删掉那一行。

## 禁止做（MUST NOT）

- ❌ 把真实凭证 / token / 私钥作为源码字面量提交。
- ❌ 把口令埋进连接串。
- ❌ "临时"硬编码一个密钥，打算以后再外部化。
- ❌ 在真实密钥上用一条假辩护注释来压制探测器。

## 关系

| 关系 | 说明 |
|---|---|
| 10 vs 03 | 03 说修根因；10 把"这个值属于配置而非代码"变成密钥类别的一条硬性、写入时的根因修复。 |
| 10 vs 09 | 同一机制（带 why 注释逃生舱的 PreToolUse 内容探测器）；09 针对压制标记，10 针对硬编码密钥。 |
| 10 vs 11 | 一同加入的姊妹探测器（v0.22）；10 管*内联的是什么*（密钥），11 管*它指向哪里*（机器特定路径）。 |

## 自检触发

- 正要在 `password` / `api_key` / `token` / `secret` / `bearer` 之后
  敲一个引号字面量。
- "只是为了先跑起来"而粘贴一个 key、token 或连接串。
- 把一个 `-----BEGIN … PRIVATE KEY-----` 块写进源文件。
- 对自己说"这个我以后再挪到环境变量里"。

## 终止条件

写一个含凭证的值，只有满足**其一**才被允许：

1. 它从环境 / 密钥库读取（非字面量）；或
2. 它是明显的占位 / 示例 / fixture（并如此标注）；或
3. 有一条相邻辩护明确说明它是必须的。

否则 → **非必须硬编码**，回到规则 03 把它外部化。
