# 规则 11 —— 禁止非必须路径依赖

## 原则

> **一个只对某台机器、某个用户、某次 checkout 有效的文件系统路径，
> 不得作为绝对字面量写死进代码。** 从运行时已知的基准派生路径 ——
> 插件根目录、当前工作目录、一个环境变量，或一个传入参数。

机器特定的绝对路径是一颗可移植性地雷：它在作者机器上能跑，在其它每台
机器、CI runner 和容器上都会崩。本仓库亲历过这个失败 —— **v0.21.1**
就是给它*自己*钩子里一个 Windows 路径可移植性 bug 打的热修（一个含
`~` 的 runner `$TEMP` 让路径正则无法解析）。规则 11 把"别硬编码 user-home
路径"变成一条写入时、根因层面的纪律（规则 03）。

## 硬强制的边界（以及不强制的部分）

忠于保守探测器哲学（"宁可漏报不误报"），只有锚定在**用户特定根**的
路径被硬强制 —— 这一类几乎从不合法可移植：

| 类别 | 硬强制？ |
|---|---|
| Windows user-home 绝对路径（`C:\Users\name\…`） | ✅ 是 |
| POSIX user-home 绝对路径（`/home/name/…`、`/Users/name/…`） | ✅ 是 |
| 字面量里的 shell home 变量（`$HOME`、`%USERPROFILE%`） | ✅ 是 |
| 字符串字面量里的 user-home 波浪号路径（`"~/…"`） | ✅ 是 |
| 系统路径（`/etc/…`、`/usr/…`、裸 `C:\`） | ❌ 仅软提示 |
| 相对路径（`./data`、`../lib`） | ❌ 放行（本就可移植） |

系统根与裸盘符**故意不**标记：它们常常合法固定，为它们做硬探测会在
正确代码上误触发。相对路径是我们想要的结果，不是违规。

## 物理拦截（钩子）

| 层 | 钩子 | 触发 | 动作 |
|---|---|---|---|
| **Edit/Write 内容** | `PreToolUse(Edit\|Write)` | `new_string` / `content` 含未经辩护的用户特定绝对路径 | **拒绝** |

散文文档（`.md` / `.markdown` / `.rst` / `.txt` / `.adoc` / `.asciidoc`）
与锁文件**豁免** —— 本仓库自己的文档就满是示意性的 `C:\Users\skyma\…`
路径，锁文件也合法地记录解析出的绝对路径。探测器只针对新写的*代码*。
（规则 10 的 `requirements*.txt` / `constraints*.txt` 例外同样适用于
本规则 —— 豁免逻辑是共享的。）

### 探测器清单

以下内容，当出现在传入内容里**且没有相邻的 "why" 辩护**时，被拦截：

| 模式 | 示例（仅示意） |
|---|---|
| Windows user-home 路径 | `C:\Users\skyma\data.csv` |
| POSIX user-home 路径 | `/home/alice/proj/` |
| shell home 变量字面量 | `$HOME`、`%USERPROFILE%` |
| 引号里的波浪号路径 | `"~/proj/data"` |

探测器想让你转而使用的可移植替代：
`Path(__file__).resolve().parent…`、`os.environ["CC_PLUGIN_DATA"]`、
运行时计算的 `Path.home()`（而非字面量）、一个 CLI 参数，或一条相对
仓库根的路径。

紧贴主机名的 `/home/<x>/` 段**不**标记（v0.24）：在
`https://host.test/home/alice/dashboard` 里它是 URL 路由而非文件系统
路径（POSIX 模式拒绝前导字符为字母 / 点 / 连字符的匹配）。
`file:///home/…` URI 仍然命中 —— 那确实是机器路径。

### 逃生舱 —— 把"非必须"操作化

用户的范围是*非必须*路径依赖。一条必须的、真正固定的路径（一个有据的
示例、一个钉在已知布局上的测试 fixture、一个真的挪不动的平台路径）在
其所在行、或紧邻行（±1）携带辩护 token 时被放行：`because` / `原因` /
`essential` / `必须` / `example` / `fixture` / `placeholder` / `占位` /
`sample` / `test data`。一条没有任何辩护的裸 user-home 路径 = 非必须
情形 = **拒绝**。

## 必须做（MUST）

1. **派生，别硬编码** —— 从插件根、cwd、环境变量或参数计算路径，
   让同一份代码能在任意机器上跑。
2. **优先相对路径** —— 把数据 / 配置锚在仓库或模块上，而非
   `/home/<你>` 或 `C:\Users\<你>`。
3. **标注真正的 fixture** —— 若某路径确实必须是固定字面量，加一条相邻
   辩护，让检查能区分意图与偷懒。

## 禁止做（MUST NOT）

- ❌ 把 `C:\Users\<name>\…` 或 `/home/<name>/…` 烤进发布的代码。
- ❌ 把 `$HOME` / `%USERPROFILE%` / `~/…` 硬编码成字符串字面量。
- ❌ 假定作者的目录布局在其它每台机器上都成立。
- ❌ 在一条真实依赖上用假辩护压制探测器。

## 关系

| 关系 | 说明 |
|---|---|
| 11 vs 03 | 03 说修根因；11 把"派生路径、别把机器写死"变成一条硬性、写入时的可移植性修复。 |
| 11 vs 09 | 同一机制（带 why 注释逃生舱的 PreToolUse 内容探测器）；09 针对压制标记，11 针对机器特定路径。 |
| 11 vs 10 | 一同加入的姊妹探测器（v0.22）；10 管*内联的是什么*（密钥），11 管*它指向哪里*（机器特定路径）。 |

## 自检触发

- 正要粘贴一个以 `C:\Users\` 或 `/home/` 或 `/Users/` 开头的绝对路径。
- 在代码里把 `$HOME` / `%USERPROFILE%` / `"~/…"` 写成字面量。
- 这条路径正确的唯一理由是"它在我机器上能跑"。
- 把你自己 shell 里的路径直接抄进要发布的源码。

## 终止条件

写一个绝对文件系统路径，只有满足**其一**才被允许：

1. 它在运行时从已知基准（插件根 / cwd / 环境 / 参数）派生，
   而非机器特定字面量；或
2. 它是明显的示例 / fixture（并如此标注）；或
3. 有一条相邻辩护明确说明它是必须的。

否则 → **非必须路径依赖**，回到规则 03 把它派生出来。
