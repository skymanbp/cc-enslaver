# 规则 12 —— 全库同步：连带更新每一处引用

## 原则

> **一次修改不是"目标文件改对了"就算完成 —— 而是仓库里所有引用、消费、
> 描述、镜像、派生这份被改内容的地方，都在同一次变更里被更新，或被显式
> 确认仍然正确，才算完成。** 同时，仓库在两次修改之间会自然积累腐坏，
> 因此还必须能按需对全库做一次"陈旧 / 过时 / 冗余 / 错误 / 漂移"扫描。

改一个文件就走人，是这套规则包此前唯一还没物理化的最高收益偷懒模式：
代码改了，README 还在描述旧行为；下游调用方还在传旧参数；翻译还镜像着
旧文本；测试还钉着旧数量。每一处都是仓库对下一位读者说的谎。规则 04/08
已经强制在修改**前**读完连带文件；规则 12 强制在修改**后**把它们写掉
（或显式确认无需改）。

## 范围 —— 两个半区

| 半区 | 触发 | 机制 |
|---|---|---|
| **被动** —— 每次修改的连带更新 | 每个 Edit / Write 会话 | 连带更新纪律 + 项目级**同步门禁**（Stop layer (i)，硬拦） |
| **主动** —— 全库刷新 | 按需（"全库更新" / "repo refresh" / "扫陈旧"） | `repo-refresh` skill：系统式全库扫描陈旧 / 过时 / 冗余 / 错误 / 漂移内容 |

## 被动半区 —— 每次修改的连带更新纪律

在 rule 08 改前必读之**后**（不是替代它），每次修改收尾必须做引用清扫：

1. **枚举引用集** —— 对改过的符号、文件名、数量、版本串、概念做全库
   Grep（代码 + 文档 + 测试 + 翻译一起）。Grep 只负责定位；这份清单是
   连带更新候选集。
2. **逐项分类** —— *必须改*（它编码了旧事实）vs *只需核对*（引用了该
   区域但仍然正确）。"我没看" 不是一个类别。
3. **同一会话改完所有"必须改"** —— 下游代码、陈述被改事实的文档、
   钉住它的测试、复制它的镜像/翻译，一起动。
4. **把清扫说出来** —— 收尾回复点名哪些连带改了、哪些核对过无需改
   （一行 `同步核对:` / `sync-check:`）。没被汇报的清扫和没做过的清扫
   无法区分。

### 同步门禁（项目级硬层）

每个项目可以把已知的连带更新不变量登记进一个入库的配置文件 —— 即让
被动半区物理化的"代码门禁"：

```toml
# .claude/cc-enforcer/sync-gate.toml
[[groups]]
name = "rules-fanout"
when = ["rules/*.md"]                       # 改了这些中的任何一个 ...
require = ["prompts/*.md", "docs/RULES.md"]  # ... 就要求同会话动过这些之一
note = "改规则必然连带注入文案 + 索引。"
```

语义：本会话编辑的文件命中某组 `when` 而该组 `require` 侧未被满足，
Stop layer (i) 就拦下 done-claim —— 除非回复用同步标记
（`同步核对` / `sync-check` / `rule 12`）显式确认核对过。可选
`mode = "all"` 要求**每一个** `require` glob 都有编辑命中（用于版本
清单这类锁步不变量）；默认 `"any"` 一个命中即满足。逃生口是故意
的："我核对过 require 侧、因为 X 所以无需改" 是合法结论；门禁强制的是
把核对**说出来**，不是盲目碰文件。**v0.27**：标记只结清**已经展示给你看过**
的组，所以流程是"先被拦一次、点名该组、再回答"。一组一次**知情**回答才是契约；
一句话盖掉你从没想过的组不是。
**v0.32**：标记还必须是**你自己**说的、而且**得说点什么**。写在代码围栏或引用块里的
标记属于引用材料、不算你的声明；占位值——`n/a`、`无`、`-` 或空值——按**缺失**处理，
照样 BLOCK。只堵最低这一档：`sync-check: 核对过了` 同样空洞，仍然放行，因为拒绝一份
诚实的报告比漏掉一份偷懒的代价更大。被确认过的组会记入会话
（`sync_acked_groups`），一次显式回答即够，之后无关的编辑不会被它
反复拦。glob 按项目相对路径 fnmatch 匹配（`*` 跨路径分隔符）。没有
配置文件 → 该项目门禁关闭（opt-in）。门禁是下限不是上限：组只编码
**已知**不变量，其余仍归上面的纪律覆盖。

## 主动半区 —— 全库刷新

被动半区让每次修改保持诚实，但清不掉已经存在的腐坏。`repo-refresh`
skill（"全库更新" / "扫陈旧" / "audit the repo" 语境自动唤起）按五类
缺陷对整个仓库（文档 + 代码）做系统式扫描：

| 类别 | 长什么样 |
|---|---|
| **陈旧（stale）** | 引用已不存在的文件 / 符号 / 路径；早已死掉的 TODO；针对已移除工作流的说明 |
| **过时（outdated）** | 在某个 commit 曾经为真、在 HEAD 已为假的数量、版本、日期、行为描述 |
| **冗余（redundant）** | 同一事实在 N 处重复而无单一源；死代码；"以防万一"留着的被取代文档 |
| **错误（wrong）** | 与当前代码矛盾的断言 —— 错误默认值、错误 CLI 标志、错误 file:line |
| **漂移（drift）** | 本应互为镜像的成对物（文档 ↔ 代码、骨架 ↔ 翻译、配置 ↔ 消费方）已经分叉 |

每条 finding 必须带 `file:line` 证据，且要么修掉要么显式报告 —— 只产出
"感觉"的扫描是 rule 01 违规。

## 物理强制（hooks）

| 层 | Hook | 触发 | 动作 |
|---|---|---|---|
| **Stop 收尾** | `Stop` **layer (i)** | edit 轮 + 某配置组 `when` 命中而无 `require` 编辑、且回复无同步标记 | **BLOCK** |

Layer (i) 按项目 opt-in（无 `sync-gate.toml` → 永不触发）、只在 edit
轮生效，并与其它 Stop 层共用一次性守卫 / 3-turn 宽限窗口。加载器与
求值器全程 failing-open：配置写坏不可能误拦。

## 必须做（MUST）

1. **收尾前先 Grep** —— 枚举所改内容的全库引用集，逐项分类。
2. **同一会话连带更新** —— 必须改的引用、文档、测试、镜像与主修改
   一起动。
3. **汇报清扫** —— 收尾回复点名连带改过的文件与核对无需改的文件。
4. **登记已知不变量** —— 某对连带关系咬过你两次，就把它登记为
   sync-gate 组，让第三次被物理拦下。

## 禁止做（MUST NOT）

- ❌ 改了实现，留着描述旧行为的文档 / README。
- ❌ 改名 / 重编号 / 改数量后只更新定义处、不更新引用处。
- ❌ 没真核对就用同步标记声称"无需变更"过门（这是 rule 01 撒谎，layer
  (g) 式的声明诚实要求同样适用）。
- ❌ 把同步门禁变绿当作全库一致的证明 —— 门只检查它登记的组
  （rule 06 验证 2b：证据覆盖面 ≠ 结论覆盖面）。

## 与其它规则的关系

| 关系 | 说明 |
|---|---|
| 12 vs 04/08 | 04/08 是输入侧：改**前**读连带文件。12 是输出侧：改**后**把它们写掉（或清掉）。同一张连带文件图，方向相反。 |
| 12 vs 06 | 06 验被改部分是否收敛；12 验**仓库其余部分**是否跟着动了。一个修复可以过 06 却搁浅十处陈旧引用。 |
| 12 vs 07 | 07 对照用户请求审计；12 对照仓库内部引用图审计 —— 那些没有任何用户消息写明的隐含义务。 |
| 12 vs 09 | 09 的批量替换纪律管全库改写**怎么执行**；12 管连带更新集**有没有被覆盖**。 |

## 自检触发器

- 你改了一个数量 / 版本 / 名字 / 路径 / 行为，正准备不 grep 其余出现
  处就收尾。
- "文档以后再更" 这句话正在成形。
- 你改了英文骨架文件却没打开它的翻译（或反过来）。
- 在一个 sync-gate 组恰好点名了该文件模式的仓库里，你把这次修改描述成
  "局部的"。

## 终止条件

修改会话只有满足**其一**才允许收尾：

1. 所改内容的每一处全库引用都已更新或核对仍正确，且收尾回复汇报了这次
   清扫；或
2. 未覆盖的剩余部分作为半成品**显式**告知用户（rule 07 半成品声明），
   而不是静默丢弃。

否则 → 正在把陈旧引用发出去；回到清扫。
